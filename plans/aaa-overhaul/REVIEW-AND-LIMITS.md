# Planning review and remaining evidence limits

16 November 2026. This record reviews the plan, not the completed website.

## Independent review corrections

The independent architecture review identified five substantive issues in the first consolidated draft. They were corrected before delivery:

1. **Mass production could precede visual proof approval.** The authoritative milestone graph now separates bounded `proof_ready` work from full completion for A07–A20. Every expansion milestone depends on A21's independent and user-reviewed approval of the three concrete native proof experiences. The milestone graph is checked for cycles.
2. **The proof milestone omitted its benchmark dependency.** A21 now requires A17's benchmark proof, including the real dataset, correctness checks, measured execution and exports.
3. **Companion package/gate IDs could conflict.** Architecture subcontracts map to A00–A27. Technical/artistic subchecks reference the master gates and do not replace them. The master milestone graph controls scheduling.
4. **Category-based operation assignment misrouted cross-domain work.** The catalogue map now assigns actual semantic exceptions, including scheduling to civic work and anatomical picking to biology, with a named domain reviewer, example-data contract and handoff requirement for every operation. A15 retains responsibility for the complete 150-operation instrument catalogue.
5. **Scope wording could allow selective omission.** The master requires complete reconciliation and an explicit disposition for each capability. An exclusion requires a recorded user-approved scope change; a proven equivalent must preserve behaviour, data and meaning.

The coverage and art documents also received reconciliation edits: the 32 DEM families are subordinate contracts, not an alternative programme; original JavaScript reference harnesses remain outside the production application; the asset bible's substantial campsite slice is one of three required proofs; and Atelier coverage means all 150 canonical operations, not merely a representative from each category.

## What remains implementation work

Static source inspection is not complete dependency extraction. The coverage ledger intentionally marks dependency closure incomplete: dynamic URLs, embedded data, transitive imports, catalogue contents and runtime-selected workloads need further extraction and execution tracing. The plan does not claim to have already acquired every source dataset, implemented every adapter, qualified every function or reviewed all existing assets.

External dataset terms and endpoint availability have not been freshly verified for acquisition during this planning task. Ecopunk's registers provide the discovery baseline; each actual acquisition must preserve the specific release, rights, attribution, source-defined sensitivity and scientific context.

The current website remains visually rejected. Existing functional/native checks are reusable evidence for limited paths, not AAA acceptance. The later staging texture-host build is unpromoted and unqualified for visual fidelity. No new implementation, dataset acquisition, bulk asset production or public deployment is asserted by this planning pack.

Performance figures in the master are proposed qualification targets on named profiles, not measured achievements. Art scores require independent written critique and actual user review; they are not self-awarded certification. Costs and delivery dates require estimates from the bounded proofs, not invented commitments.
