# Native architecture and complete experience validation

Date: 16 November 2026. Status: comprehensive implementation-plan contribution, not a claim that the overhaul is finished. Read alongside the programme's art direction, world design, audience/content and delivery plans.

## 1. Non-negotiable outcome

Build a human centric computing ecosystem experience spanning space, Earth, physics, biosphere, biology, society, knowledge, socioeconomic relationships and the infosphere. Its explorable world must be a coherent authored artwork that exposes real software and actual data. It must not become decorative places linking to old documentation.

Every migrated capability must work INSIDE the new environment: discover it, understand its purpose and human significance, inspect underlying data, configure and execute a real run, cancel work, inspect results and failures, compare evidence, and export actual artifacts. Accessible reading, tables and non-spatial operation are alternative presentations of the same application state and data. Legacy links, screenshots, videos, iframes, preserved files and green badges do not constitute completed migration.

The browser application is native Rust/WASM, using actual QualiaDB, Vibe and Etalon implementations. Page code initialises the generated WASM loader only. No authored JavaScript world, geometry builder, controller, benchmark orchestration or substitute reasoning engine is permitted in the production browser. Rust owns lifecycle, native API calls, transport, DOM accessibility and hardware input delivery. Vibe owns authored experience policy, journeys, camera/artistic transitions and instrument workflows. Real Q42 graphs own entities, relationships, data descriptors, provenance, claims, locale resources, experiment definitions and results.

Default language is Australian English (`en-AU`). Internationalisation includes Unicode, non-Latin scripts, reading direction, translated accessible names, locale formatting, language fallback and translation provenance. Language, declared purpose and support needs may alter presentation; they must not silently alter rights or infer sensitive personal status.

Use `webizen-website` as the independently releasable experience/publication repository. It owns authored world programmes, content graphs, locale packs, application integration, art recipes/manifests, deployment and end-to-end evidence. QualiaDB remains the codec/query/geometry owner, Vibe its language/runtime owner, Synth the producer, Hypermedia the production-morphism owner, and Etalon the rendering/signal provider. Do not fork engine algorithms into the website just to obtain a result.

Each release composition pins repository commits, engine features/profiles, compiler and binding-generator versions, artifact digests and source rights. Reconcile actual Poet ownership: the inventory deliberately marks its source owner unresolved. That is a release dependency, not justification to omit Poet or assign it to Synth by assumption.

## 4. Real data across scales

Q42 is the semantic spine; it does not replace every native binary representation. Relate stable semantic entities to content-addressed resources: real Q42 volumes for knowledge/claims/context; `.10d` for geometry/material/UV metadata; `.m64` for supported geospatial/occupancy representations; `.emf` for actual electromagnetic field cells; HMC for packaged deterministic production dependencies; and appropriate image/audio/video/document/tabular/model formats for their actual runtime inputs/outputs. Preserve original source bytes and conversion receipts. Do not rename JSON to native extensions or treat render previews as scientific source data.

Each dataset needs stable ID, owner/source, version/release/date, rights or scoped permission, source/derivative hashes, codec/version, units/coordinate frame, temporal coverage, schema/ontology, counts, ingestion recipe, limitations, access classification, partition/index map and semantic validation evidence. Each run adds exact runtime/build, parameter/input digests, execution environment, timings, resource observations, output digests and outcome.

Space, Earth, ecosystem and human-scale views share stable identities and declared transforms. Keep astronomical, geodetic, ecological and local artistic coordinates distinguishable. Provide scale, units and time inspection. Visually compressed space must declare its presentation scale while preserving true values. Scientific data accuracy must not be conflated with an artistic landscape. The infosphere overlays evidence and relationships without reducing nature or human beings to decorative nodes.

Publication flow: authorised source -> verified bytes/metadata -> existing native ingestion -> partitions/indexes -> graph descriptions and relationships -> count/unit/identity checks -> original/native semantic comparison -> immutable release artifacts and versioned pointer. Quarantine failed candidates without mutating accepted versions. Read historical block/compressed formats through their actual codecs or perform an explicit verified migration. Never rebuild a second browser Q42 decoder.

Public graphs must exclude private location history, credentials and personal records. Sanitised broad journey chapters are deliberately distinct from precise geospatial datasets. Purpose-based pathways use declared choice and graph relationships; authority is checked separately. Human rights/support principles must be demonstrated through controls, explanations, refusal/appeal/provenance interactions and accessible operation, not merely claimed in prose.

## 5. Integrated instruments and the infosphere laboratory

The laboratory is a working place in the world and an accessible non-spatial workspace over the same state. Instruments also appear in relevant contexts: sky/space for scale/coordinates; river/terrain for geodesy/fields; canopy for ecology; biology for anatomy/scientific records; civic commons for norms/credentials/cooperation; atelier for media/production; observatory for knowledge/query/evidence. Cross-domain workflows remain possible.

Every instrument requires this complete lifecycle:

1. A plain-language question, significance, involved modules, input dataset/version and honest evidence status.
2. Inspect actual inputs: graph neighbourhoods, records, geometry, field slices, media, source/query, units, parameter bounds and provenance. A thumbnail alone is not data inspection.
3. Select/edit data and parameters through native controls; validate before running; explain resource/download requirements and whether computation occurs in the browser or an actual service.
4. `prepare -> ready -> queued -> running -> succeeded | failed | cancelled | unavailable` transitions tied to real jobs. Cancellation reaches the native worker/job or bounded chunk boundary and releases resources. Ignoring a late result is not cancellation. Non-interruptible calls must be isolated and bounded, with honest cancellation semantics.
5. Real execution with progress counters reflecting completed work, not animated timers. Retain run ID, immutable input/parameter hashes and actual events/results.
6. Inspect success and failure in the environment: values, units, assertions, geometry/plots, records, error locations, raw timing samples and provenance. Change an input, rerun, compare, reset, and export the actual output plus receipt.
7. Equivalent keyboard/screen-reader and reduced-motion operation, native tables, non-colour outcomes and export. Reduced motion must not disable computation. A device without WebGPU must retain all supported CPU/WASM/service-backed instruments in the new non-spatial app.

Explain each element's function, distinctive approach, human significance, relationship to the ecosystem and evidence limits. Technical receipts are available progressively; they are not the primary public-facing story. Developers and AI can inspect the same versioned structured data, while government, UN-related audiences, ordinary people and investors receive appropriate authored pathways over it.

## 8. Native material fidelity: existing executable route

The current world used native MAT1 factors but omitted complete texture hydration. Correct fidelity at the producer/material boundary, not through repeated tone adjustments.

1. Author geometry, UVs and tangent frames. Existing indexed operations include `unwrap_slim`, `compute_mikktspace`, `synthesize_maps`, `bake_pbr_materialx` and `pack_pbr_set`; invoke the appropriate real operation and inspect its outputs.
2. Imported GLB must preserve `TEXCOORD_0`, normals/tangents, image resources and material texture bindings. `manifold_ops.rs:702` consumes imported UVs, `:783` tangents, `:966` MAT1, and `:972` emits each texture dependency as digest/MIME/resource.
3. For non-imported materials, `compile_10d_pbr` accepts `bsdf_graph`, `colour_map`, `normal_map`, `orm_map`, `source_10d` and `tangents`. Encoded PNGs become MAT1 SHA-256 references. ORM binds metallic-roughness and occlusion. UV01 is required; normal maps require aligned tangent data. Explicit bindings cannot override existing imported GLB materials; produce the correct GLB or use an actual codec reseal with full validation.
4. Publish `.10d` and actual texture bytes as a single versioned dependency graph/HMC. Keep global material IDs consistent across split assets. Retain real provenance gates; do not clear refusal flags or invent external licences/signatures.
5. Before scene submission, call `QualiaPortal::load_texture_encoded(digest32,mime,encoded,role,cutoff)`. Roles 0/1/2/3 mean sRGB colour / linear tangent normal / linear packed data / alpha-mask colour. Mask cutoff must match the actual material. Current encoded input bound is 4 MiB per dependency. Engine verifies digest and decoding and owns mip/residency semantics.
6. Native scene assembly reads MAT1 and UV01; native mesh upload generates UV-aligned tangent frames where necessary. Etalon selects textures by digest, colour space and mip semantic. No authored JS texture or tangent path is needed.

Required unimplemented guards: every used-material reference must resolve to a resident matching dependency; validate UV counts/tangent basis; refuse silent neutral textures; require actual material-pipeline upload; refuse colour-only fallback for approved textured art. `materials.rs:298` deliberately allows typed neutral maps for missing dependencies, and scene upload can fall back to coloured geometry. Host fidelity admission must detect degradation rather than call it success. Receipts identify used/resident/omitted maps and reasons.

Do not feed `bake_pbr_materialx` world-normal output blindly to a tangent-normal slot. Inspect the convention and use an actual tangent-space map or verified conversion. MaterialX generation is an authoring artifact, not proof that the browser reads MaterialX directly; the verified runtime path is MAT1 plus native image hydration.

Visual review includes close/grazing views, UV seams, tangent orientation, alpha-mask foliage, roughness/metal/AO channels, global material identity, terrain variation, bark/leaves, water and mobile mip quality. File existence, HTTP200, map counts and triangle counts are not visual approval.

## 9. Camera, lighting and presentation parity

The old `site/world/scene.js:49` uses vertical FOV 49 degrees desktop / 58 mobile. Native Etalon `spatial_math/camera.rs:12` fixes tangent half-FOV 0.41421357 (45 degrees), so identical eye positions frame differently. Vibe can match target-plane footprint by multiplying distance by `tan(old_fov/2)/tan(22.5deg)` (about 1.10 desktop, 1.34 mobile), alongside the original mobile framing cap `min(1.35,1/aspect)`. This approximates framing, not exact perspective. True FOV parity requires a separately owned reviewed native API change with projection/picking/AO tests, rather than undocumented compensation.

The grey veil had a concrete cause: portal graphics defaults environment fallback radiance to [0.18,0.22,0.26]; the no-probe shader adds this independently of albedo. Existing `set_environment_probe_data(&[], &[0,0,0])` removes that constant while retaining sun/material-dependent ambient. Daylight atmosphere preset 1 uses density 0.0004 per world unit; preset 0 uses no fog. These diagnostics do not substitute for real authored lighting/probes and surface maps.

Create a fixed native reference scene/camera manifest: space/Earth scale, wide landscapes, human eye level, hero objects, close-up materials and portrait views. Record eye/target/FOV or compensation policy, exposure, colour space/tone mapping, sun/probes, atmosphere, dimensions, actual backend and quality flags. Compare with approved art direction and previous useful features at equal framing. Require inspected actual output after every material/rendering change.

Generated-loader-only permits native-created HTML controls/accessibility surfaces. The final non-spatial application must expose the same data and instrument operations when graphics is unavailable. A reading link was a prototype failure state, not acceptable final functional equivalence.
