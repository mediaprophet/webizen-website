## Public site

`https://webizen.au/?ewm=1` loads the page, then the living world does not start.

Played in a browser on 19 November 2026, WebGPU present:

- Status ends on: "The living world could not start on this device. The reading view is always available."
- Console: `Could not load /publication/world.q42: 404` from `site/world/gl-debug.js`.
- `window.__webizenNativeInit` stays null. The canvas never receives a scene.
- WASM, `webizen_world.js`, `scene.q42`, `scene.json`, `catalog.q42`, and `species-catalog.q42` return HTTP 200.
- `https://webizen.au/publication/world-d8d19492c1e6e4a0.q42` returns HTTP 200. That is the file named by `publication/generated/current.json`.
- `https://webizen.au/publication/world.q42` returns HTTP 404.
- `https://webizen.au/intenteco/eucalyptus-camaldulensis/dist/lods/eucalyptus-camaldulensis-lod1.10d` returns HTTP 404.

Cause of the 404: `native/world-host/src/runtime/boot.rs` fetches `/publication/world.q42` before it draws anything. Locally, `tooling/world_server.py` maps `/publication/` to `publication/generated/`, and `world.q42` is a 17,092-byte alias of `world-d8d19492c1e6e4a0.q42`. That alias is not in git (`git ls-files` omits `world.q42` and `world.ttl`). Cloudflare Workers deploys the `_site` tree built from the checkout, so the alias never ships. The hashed volume does.

A second gate sits behind that 404. `site/index.html` sets `data-scene="/production/lush-woodland/scene.q42"`. If the query is not `?ewm=1`, boot returns: "The woodland streams when you add ?ewm=1." The bare homepage is therefore also a failure, by construction. `streaming.default` in the catalog is still refused when true (`catalog.rs`). That refusal stays. The resident world has to draw without turning streaming on.

Species, grasses, and the person are not on the public origin. `world_server.py` mounts `/intenteco/<slug>/` onto `C:\github\eco-intent`. Nothing in `build_pages.py` copies those files into `_site`. The page also sends `Cross-Origin-Embedder-Policy: require-corp`. A GitHub raw mirror does not satisfy that policy, so the Tier-2 resolver in `admission.rs` cannot fill the gap on webizen.au.
