# Observer-relative paths through a human-centric computing ecosystem

Design addition, 16 November 2026. This extends the natural-world/infosphere brief and human-support demonstrations. The proposed website is powered by versioned `.q42` graphs and supported Vibe behaviour, with human-authored meaning and presentation. Its paths adapt to the **status of the observer**, circumstance, purpose and stated support requirements.

## Existing implementation to build upon

The inspected QualiaDB source supplies these concepts; they should not be replaced by a disconnected website persona framework:

| Source | Existing concept | Website integration implication |
| --- | --- | --- |
| `qualia-core-db/src/entity_view/observer.rs` | `ObserverStatus`: Principal, Peer, Guardian, Steward, Public, Instrument, Auditor | Observer relationship is session-bound. The same person can participate in different roles. It is not a ranking of human worth or expertise. |
| Same module | `RepresentationWing`: Private, Offered, Commons; `AffordanceBits`: open/share/enter/edit | The same stable entity can have different permitted representations and actions. |
| `entity_view/circumstance.rs` | `Circumstance`: role, audience, quorum, environment, evaluatory focus, place hint | Circumstance supports context-sensitive presentation. The file explicitly describes full path steering as host composition; it does not itself enforce rights. |
| `entity_view/rights_filter.rs` | `decide_view_with_grant`, `decide_view`, `filter_visible` | Reuse actual filtering and action decisions, with host authentication, policy and delegation qualification. This pure filter explicitly is not a cryptographic lock. |
| `entity_view/entity_id.rs`, `package.rs`, `attribution.rs`, `projection.rs` | Stable identities, representation packages, typed attribution, flat/spatial projection | A person can change presentation without changing the identity, source or meaning of the thing being explored. |
| `entity_view/capability_report.rs` | Design capability report and host expectations | Consume as source evidence and integration guidance, then qualify the real deployed host. A static report is not a runtime receipt. |
| `docs/js/qualia-shell.js` | Human-centric observer standpoint explicitly decoupled from the camera lens; `set_standpoint` bridge | Camera position, sociotechnical relationship and informational viewpoint are related design dimensions, not interchangeable authority controls. |

These are verified source findings, not a claim that the complete website adaptation workflow has been tested. The separate spatiotemporal `ObserverStatus` describing physical motion must not be confused with the socio-informatics observer type above.

## What constitutes an observer context

Keep the following dimensions distinct but related:

- **Relationship and authority:** the actual principal/peer/guardian/steward/public/instrument/auditor relationship, verified grants and relevant scope.
- **Purpose:** what the person wants to understand or accomplish now; who defined that purpose and who may change it.
- **Circumstance:** audience, environment, temporal/place context, quorum and current evaluatory focus.
- **Needs and support:** explicitly stated or appropriately sourced presentation, interaction, language, assistance and participation requirements.
- **Knowledge and attention:** the level of explanation the person requests, current inquiry and chosen disciplinary perspective. Do not equate expertise with authority.
- **Available means:** device/runtime capabilities, bandwidth, time and resources relevant to the activity.

The public website starts in a public reading/exploration context. The Rust observer enum's default `Principal` is not a reason to grant an anonymous browser principal authority. A visitor choosing “researcher” or “developer” changes the offered explanation, not authenticated permissions. Role-specific demonstrations can use explicit synthetic sessions without implying access to real private data.

## One river, several meaningful paths

| Observer purpose/circumstance | First experience | Natural progression | Subtle presentation change |
| --- | --- | --- | --- |
| A person learning about the river | A comprehensible observation in its living setting | Follow source → understand context → ask a question → discover related life | Plain language, slower reveal, local scale, optional explanation; no forced onboarding form |
| A community participant contributing knowledge | A place, contribution and intended community purpose | Inspect attribution → choose a supported contribution path → understand terms and recipients | Bring relationships and cooperative activity forward; maintain direct access to underlying evidence |
| A researcher investigating a claim | The observation, units, uncertainty and provenance | Compare evidence → inspect a model → run a qualified workload | Instruments, scales and source annotations become prominent; retain the human/ecological context |
| A person seeking a supported way to participate | The same question through a chosen accessible route | Complete the same task → inspect the same result → request available assistance | Equivalent reading, keyboard/touch and supported media paths; preferences remain adjustable |
| A public institution evaluating a proposed use | Human purposes, responsibilities, affected participants and evidence | Inspect interpretation → observe support/authority outcomes → assess deployment qualification | Put accountability and practical effects first; provide deeper technical detail on demand |
| A developer building a relevant tool | A working demonstration linked to its source | Inspect graph → change supported input → run Vibe/host operation → inspect receipt | Reveal actual inputs, operations, runtime limits and integration contracts without replacing the world with a console |
| A partner evaluating sustainable participation | Useful activities, dependencies, resources, responsibilities and qualification | Understand component relationships → inspect evidence → examine scoped opportunities | Reveal socioeconomic relationships and delivery conditions; no invented adoption or financial claims |

The same `.q42` entities support each path. Human-rights principles, purposes, needs and support requirements remain visible through behaviour in every path. Visitors can change direction, compare perspectives and use the direct map/index at any time.

## Proposed execution and publication flow

1. Import pinned module facts, source references, evidence and human-authored descriptions into a versioned publication graph. Give places, organisms, works, activities, people/roles in synthetic scenarios, concepts, capabilities, demos and relationships stable IDs.
2. Publish a genuine public `.q42` bundle plus equivalent semantic HTML and compact indexes. Restricted resources belong in appropriate host-controlled storage and delivery. Hiding a mesh or node in a viewport does not remove bytes already sent to a browser.
3. Establish a bounded observer session with its selected purpose, circumstance and stated support requirements. Resolve actual authority using the selected host and source contracts.
4. Query/filter the graph for permitted representations and actions using the existing kernel and host integration. Record the graph revision and effective runtime/profile.
5. Execute supported Vibe behaviour to select and sequence the proposed path, invoke qualified operations, and compose the relevant experience. Use real admitted APIs from the chosen host; do not invent a `hypermedia.*` operation for navigation.
6. Render the same selected entities as an immersive scene, reading route, source/evidence view or technical interface. Synth-produced assets and Etalon/QualiaPortal rendering are tied to explicit qualified profiles and production receipts.
7. Adapt at meaningful boundaries when the visitor changes purpose/context or requests support. Preserve orientation, current work and a usable route back. Keep an inspectable explanation of the proposed path and available alternatives.

This is a proposed website composition of existing foundations. Availability of the graph, language and view kernel does not by itself qualify the whole deployment path.

## Subtle, resonant methodology

Adapt the **invitation**, sequence, emphasis, expressive form and scale—not the underlying evidence to suit an audience. A relationship may first appear as a visible effect in a landscape, then as a story, then as a sourced assertion, then as an executable technical object. A visitor does not need to see all those levels at once.

Use framing, light, sound, spatial proximity, pacing, labels and meaningful affordances to guide attention. The visitor can pause, inspect, flatten the view, change direction or open the complete technical index. Do not impose a scenic journey on someone who needs a direct answer.

Information geometry, socioeconomic geometry and knowledge geometry should be discoverable through typed relationships, different perspectives and observable consequences. Where geometry has a specific mathematical implementation, expose that implementation and its limits. Where it is an authored spatial explanation, identify it as such.

## Demonstration and acceptance

The next approved vertical slice must let reviewers select at least three explicit synthetic observer contexts and see different useful paths through the **same graph and place**. Include:

- A change of purpose that changes the recommended next actions and explanation.
- A stated support requirement that changes presentation while preserving task/result equivalence.
- An actual permitted/refused operation under the selected host policy, with a comprehensible explanation and supported alternative where available.
- A correction/contestation that changes an actual dependent query or explanation without silently rewriting provenance.
- An immediate switch between immersive and conventional representations with stable entity identity and context.
- A route explanation identifying the input context, graph version, authored rules, selected entities/actions, runtime and result.

Verify unknown/anonymous context, changed or expired grants where supported, stale projections, insufficient device capability, cancellation, keyboard navigation and recovery. These checks support truthful claims about the ecosystem; they do not establish universal legal or human-rights compliance.

Public copy should lead with the person's activity. Technical visitors can inspect the observer schema, graph selection, Vibe source and execution evidence. This makes the website itself a demonstration of human-centric computing rather than a set of claims about it.
